H3 RESOLVED Missing error handler on deleteTask subscriptions

Fixed: Added a SnackbarService (providedIn: 'root') with signal-based state and auto-dismiss after 5 seconds. Both facades now handle success and error in deleteTask, surfacing feedback via snackbar. 

// Both facades now:
deleteTask(taskId: string): void {
  this.deleteTaskUseCase.execute(taskId).subscribe({
    next: () => {
      this.store.clear('TASKS');
      this.loadTasks();
      this.snackbar.show('Task deleted successfully', 'success');
    },
    error: () => {
      this.snackbar.show('Failed to delete task. Please try again.', 'error');
    },
  });
}

M1 Mock interceptor mutates shared array in-place mock-api.interceptor.ts
core/mock/mock-api.interceptor.ts — lines 170, 182, 198

Three operations directly mutate the module-level mockTasks array using push, splice, and index assignment. This contradicts the project's immutability rule and teaches incorrect patterns in a sample app. 

mockTasks[index] = updated;   // index assignment mutates
mockTasks.splice(index, 1);   // splice mutates in-place
mockTasks.push(newTask);      // push mutates in-place
Suggested fix: Reassign the array reference using filter, map, and spread instead of mutating in-place. Declare with let to allow reassignment.
